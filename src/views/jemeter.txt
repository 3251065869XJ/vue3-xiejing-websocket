JMeter 实现100并发用户、累计100万次请求压测配置
 
整体思路：100个线程（并发用户） 持续施压，总请求数达到100万次，支持单/双接口，分步骤搭建+参数说明+运行校验。
 
一、前置准备
 
1. 安装JMeter（5.4+ 稳定版），配置JDK环境
2. 准备被测接口地址、请求方式（GET/POST）、请求头、入参、Cookie/Token等前置依赖
3. 机器建议：压测机预留足够内存，修改  jmeter.bat/jmeter.sh  堆内存（默认偏小，大数据量易OOM）
- 打开 bin/jmeter.bat ，修改： set HEAP=-Xms2g -Xmx4g （根据服务器配置调整）
 
 
 
二、完整测试计划搭建（分步操作）
 
步骤1：新建测试计划 & 线程组（核心：100并发用户）
 
1. 打开JMeter → 右键测试计划 → 添加 → 线程组
2. 线程组参数配置（关键）：
- 线程数(用户)： 100  （模拟100个并发用户）
- Ramp-Up时间(秒)： 10  （10秒内逐步启动100个线程，避免瞬间打爆服务；可设0瞬间拉起）
- 循环次数：选择永远 （重点：让线程持续跑，直到总请求到100万）
- 不勾选 延迟线程创建直到需要 
 
逻辑：100个常驻并发线程，不停调用接口，累计请求达到100万后手动停止/通过控制器控制停止。
 
 
 
步骤2：添加接口请求（单接口 / 两个接口两种场景）
 
场景A：只压测1个接口
 
1. 右键线程组 → 添加 → HTTP请求
2. 配置接口信息：
- 协议： http/https 
- 服务器名称或IP：接口域名/IP
- 端口号：默认80/443填对应值
- 路径：接口URI（如  /api/test ）
- 请求方法：GET/POST，填写参数、请求体、请求头
 
场景B：压测2个接口（串行轮流调用）
 
在线程组下添加两个独立HTTP请求，上下排列，线程会按顺序依次调用接口1 → 接口2，循环往复。
 
如需两个接口随机调用：在线程组下添加 随机控制器，再把两个HTTP请求放入控制器内。
 
补充（可选）
 
- 若接口需要Token/登录：线程组顶部添加HTTP请求做登录，搭配正则表达式提取器提取Token，供下游接口使用。
- 全局请求头：线程组添加 HTTP信息头管理器，统一配置 Content-Type 、 Authorization 等。
 
 
 
步骤3：添加监听器（统计请求数、结果）
 
用来实时查看总请求数、成功率、响应时间，必加：
 
1. 察看结果树：调试阶段用，正式压测建议关闭（消耗性能）
2. 聚合报告：核心报表，查看TPS、错误率、总请求数
3. 活动线程图：监控100个并发线程状态
 
 
 
步骤4：控制总请求数 = 100万次（两种实现方式）
 
需求：100并发，累计执行1000000次请求后自动停止，分两种方案。
 
方案1：手动统计 + 手动停止（简单，新手首选）
 
1. 按上面配置好线程组（线程数100，循环=永远）、接口、聚合报告
2. 点击启动运行压测
3. 实时查看聚合报告中  样本  列（即总请求数）
4. 当样本数接近  1000000  时，点击停止即可
 
方案2：用「计数器+逻辑控制器」自动停止（精准到100万请求，推荐正式压测）
 
适合无人值守，达到100万请求自动终止压测：
 
1. 右键线程组 → 添加 → 配置元件 → 计数器
- 名称：全局请求计数器
- 引用名称： total_req 
- 起始值： 0 
- 增量： 1 
- 勾选 仅本线程  取消（全局计数，所有线程共用）
- 最大值： 1000000 
2. 右键线程组 → 添加 → 逻辑控制器 → 如果控制器
- 条件（勾选  使用JavaScript ）：
javascript
  
${__jexl3(${total_req} >= 1000000,)}
 
3. 在如果控制器内部，添加 测试动作
- 测试动作 → 操作： 停止测试 
4. 将HTTP接口请求 放到 如果控制器外层（正常执行请求，计数满则触发停止）
 
原理：每执行一次接口，计数器+1，总数≥100万时自动停止整个测试。
 
 
 
三、关键优化配置（必做，避免JMeter自身瓶颈）
 
1. 关闭多余监听器（提升压测性能）
 
正式压测时：
 
- 禁用/删除 察看结果树、图形结果（IO/内存消耗极大）
- 只保留 聚合报告，或使用命令行运行（最优）
 
2. 命令行运行（推荐，大数据量压测）
 
GUI界面运行100万请求容易卡顿、丢数据，正式压测必须用命令行：
 
1. 先在GUI调试好脚本，保存为  test_100user_100w.jmx 
2. 打开CMD/终端，进入JMeter  bin  目录，执行命令：
 
bash
  
# Windows
jmeter -n -t test_100user_100w.jmx -l result.jtl -e -o report

# Linux/Mac
./jmeter -n -t test_100user_100w.jmx -l result.jtl -e -o report
 
 
参数说明：
 
-  -n ：非GUI模式运行
-  -t ：指定jmx脚本文件
-  -l ：把结果写入jtl日志文件
-  -e -o report ：压测结束后自动生成HTML可视化报告
 
3. 禁用DNS缓存、请求重试（可选）
 
添加 HTTP请求默认值，关闭不必要超时重试，贴合真实用户场景。
 
 
 
四、参数验算 & 场景说明
 
当前配置：
 
- 并发用户：100 个（同时在线）
- 总目标请求：1000000 次
 
举个参考（理论值）：
假设单线程每秒发 5 次请求：
 
- 整体TPS = 100 * 5 = 500
- 跑完100万请求耗时 ≈ 1000000 / 500 / 60 ≈ 33.33 分钟
 
可根据接口响应速度预估压测时长。
 
 
 
五、常见问题排查
 
1. JMeter报错OOM（内存溢出）
修改  jmeter.bat  堆内存，加大  -Xmx  值；关闭GUI、关闭结果树。
2. 请求数统计不准
计数器取消「仅本线程」，使用全局计数；优先命令行运行。
3. 并发没达到100
Ramp-Up时间不要设置过大；检查接口是否阻塞、有无长等待。
4. 大量请求失败
核对接口地址、请求头、Token、入参；检查服务端限流/防火墙。
 
 
 
六、快速总结（最简配置清单）
 
1. 线程组：线程数=100，循环=永远，Ramp-Up=10s
2. 线程组下添加 1个 / 2个 HTTP请求（被测接口）
3. 加聚合报告（统计总请求数）
4. 方案一：GUI运行，看聚合报告「样本数」到100万手动停止
5. 方案二：加计数器+如果控制器+测试动作，自动停测
6. 正式压测改用 命令行模式，性能最优
